# Ruby 3.4.1 Upgrade Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Upgrade the application runtime, dependency lockfile, and deployment configuration to Ruby `3.4.1` and resolve any compatibility issues required for the app to install, build, and test on that version.

**Architecture:** Keep the upgrade narrow. First retarget the runtime pins and Bundler Ruby requirement, then regenerate or update the bundle under Ruby `3.4.1`, and finally run project verification to surface any incompatible gems or code paths. Only make the minimum compatibility fixes needed to restore a green install/build/test path.

**Tech Stack:** Ruby 3.4.1, Bundler, Rails 7.2.2.1, RSpec, Minitest, Yarn, Docker

---

### Task 1: Pin Ruby 3.4.1 in project configuration

**Files:**
- Modify: `.ruby-version`
- Modify: `Gemfile`
- Modify: `Dockerfile`
- Modify: `Dockerfile.development`

**Step 1: Write the failing test**

Check the current pins and confirm they still reference the old runtime.

Run: `rg -n "3\\.2\\.6|^ruby " .ruby-version Gemfile Dockerfile Dockerfile.development`
Expected: matches show `3.2.6` and no explicit `ruby "3.4.1"` entry in `Gemfile`

**Step 2: Run test to verify it fails**

Treat the old pin as the failure condition for this task.

Run: `test "$(cat .ruby-version)" = "3.4.1"`
Expected: FAIL because the current version is `3.2.6`

**Step 3: Write minimal implementation**

- Change `.ruby-version` to `3.4.1`
- Add `ruby "3.4.1"` near the top of `Gemfile`
- Change `ARG RUBY_VERSION=3.4.1` and `FROM ruby:3.4.1` in both Dockerfiles

**Step 4: Run test to verify it passes**

Run: `rg -n "3\\.4\\.1|^ruby " .ruby-version Gemfile Dockerfile Dockerfile.development`
Expected: all project runtime pins reference `3.4.1`

**Step 5: Commit**

```bash
git add .ruby-version Gemfile Dockerfile Dockerfile.development
git commit -m "chore: pin ruby 3.4.1"
```

### Task 2: Refresh the bundle on Ruby 3.4.1

**Files:**
- Modify: `Gemfile.lock`

**Step 1: Write the failing test**

Inspect the lockfile metadata and bundle behavior before regeneration.

Run: `bundle platform --ruby`
Expected: either old Ruby metadata or a mismatch against the newly pinned `3.4.1`

**Step 2: Run test to verify it fails**

Run: `bundle check`
Expected: FAIL or indicate missing gems until the bundle is refreshed under Ruby `3.4.1`

**Step 3: Write minimal implementation**

Run Bundler with Ruby `3.4.1` and update the lockfile:

```bash
bundle update --ruby
bundle install
```

If Bundler reports Ruby `3.4.1` is unavailable locally, install or use the local Ruby `3.4.1` runtime before retrying.

**Step 4: Run test to verify it passes**

Run: `bundle platform --ruby`
Expected: `ruby 3.4.1`

**Step 5: Commit**

```bash
git add Gemfile.lock
git commit -m "chore: refresh bundle for ruby 3.4.1"
```
